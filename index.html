01

计算机组成与体系结构

5–6 题约 7%

数据表示与运算

进制转换、原码 / 反码 / 补码 / 移码（负数补码 = 反码 +1，补码可直接加减）
浮点数运算：对阶 → 尾数计算 → 规格化；表示范围
校验码：奇偶校验、海明码（纠错位数）、CRC 循环冗余校验
定点数表示范围、溢出判断

CPU 与指令系统

运算器（ALU、累加器、PSW）与控制器（PC、IR、时序）
寻址方式：立即、直接、间接、寄存器、相对、基址、变址
CISC 与 RISC 的区别
指令流水线：周期、加速比、吞吐率计算
流水线执行时间 = 一条指令完整时间 +（指令数 −1）× 流水线周期；流水线周期取各段最长时间。

存储与 I/O 系统

Cache：作用、命中率与平均访问时间、三种映射（直接 / 全相联 / 组相联）
存储层次：寄存器—Cache—主存—辅存；虚拟存储器
I/O 控制方式：程序查询 → 中断 → DMA（DMA 不经过 CPU、直接内存存取）
总线分类（数据 / 地址 / 控制）、常见总线
可靠性计算：串联 R=R₁R₂…、并联 R=1−(1−R₁)(1−R₂)…；性能指标 MIPS、MTBF
考点精讲：把组成原理的「必算点」讲透
1. 原码 / 反码 / 补码 / 移码（高频）
  • 正数：三码相同，符号位为 0。
  • 负数：原码符号位为 1；反码 = 原码数值位取反；补码 = 反码 +1（逢二进一）。
  • 移码 = 补码符号位取反，常用于表示浮点数阶码，便于比较大小。
  • n 位二进制：原码/反码表示范围 −(2n−1−1) ~ +(2n−1−1)；补码范围 −2n−1 ~ +(2n−1−1)，多表示一个最小负数。
例：−127 的 8 位补码：原码 11111111 → 反码 10000000 → 补码 10000001。而 −128 的 8 位补码是 10000000。
2. 浮点数运算

步骤：对阶（小阶向大阶看齐，尾数右移）→ 尾数加减 → 规格化（左规/右规）→ 舍入 → 判溢出。规格化后尾数最高数值位应为有效位（原码规格化为 0.1…，补码规格化为 1.0… 或 0.1…）。

3. 校验码
  • 奇偶校验只能检奇数位错、不能纠错；
  • 海明码可检错并纠一位错，校验位位数 k 满足 2k ≥ n+k+1（n 为信息位数）；
  • CRC 循环冗余校验用生成多项式做模 2 除法，可检错，常用于数据链路层。
4. Cache 与平均访问时间

平均访问时间 T = h·Tc + (1−h)·Tm（h 为命中率，Tc 为 Cache 时间，Tm 为主存时间）。三种映射：直接映射（一个主存块只能放固定行，易冲突）、全相联（任意放，最灵活但比较器最多）、组相联（折中，先按组号定位再在组内全相联）。

5. 指令流水线

流水线周期 = 各段中时间最长的一段；总时间 = 一条指令完整执行时间 +（指令数−1）× 流水线周期；吞吐率 = 指令数 / 总时间；加速比 = 串行总时间 / 流水总时间。

6. 可靠性
  • 串联：R = R₁·R₂·…·Rn（任一部件坏，系统坏）；
  • 并联：R = 1−(1−R₁)(1−R₂)…（冗余，全部坏系统才坏）；
  • 混联先并后串或先串后并，逐层化简。

操作系统

5–6 题约 7%

进程管理

进程三态 / 五态及状态转换、进程与线程区别
进程调度算法：FCFS、SJF 短作业优先、时间片轮转、优先级（会算周转/等待时间）
PV 操作（信号量）：前趋图、互斥与同步、生产者-消费者、读者-写者
死锁：四个必要条件、资源分配图、银行家算法（安全序列）
死锁最少资源数：若 n 个进程各需 k 个同类资源，则 n(k−1)+1 个资源可保证不死锁。

存储管理

分区、分页、分段、段页式管理的特点与区别
逻辑地址 → 物理地址换算（页号、页内地址、页表）
页面置换算法：OPT 最佳、FIFO（Belady 异常）、LRU、时钟算法（会模拟缺页次数）

设备与文件管理

磁盘调度：FCFS、SSTF 最短寻道、SCAN 电梯、CSCAN（会算磁头移动道数）
SPOOLing 假脱机技术、缓冲技术
文件物理结构：连续 / 链接 / 索引（多级索引、混合索引容量计算）
位示图法管理磁盘块、树形目录结构、绝对/相对路径
考点精讲：操作系统的「计算题套路」
1. 进程调度：周转 / 等待时间
  • 周转时间 = 完成时间 − 到达时间；带权周转时间 = 周转时间 / 服务时间；等待时间 = 周转时间 − 服务时间。
  • FCFS 按到达先后；SJF 选服务时间最短（平均等待最小，可能饿死长作业）；时间片轮转按固定片轮流；优先级调度有抢占/非抢占。
2. PV 操作（信号量）
  • P（申请）：S=S−1，若 S<0 则阻塞；V（释放）：S=S+1，若 S≤0 则唤醒一个等待进程。
  • 互斥：临界资源信号量初值 = 1；同步：前趋信号量初值 = 0，前驱完成后 V，后继执行前 P。
  • 生产者-消费者：empty=n、full=0、mutex=1 三个信号量；P 操作顺序不能错（先同步后互斥），否则死锁。
3. 死锁

四个必要条件：互斥、请求保持、不剥夺、循环等待（缺一不可，破坏其一即可预防）。银行家算法：每次试探分配后系统仍处于安全状态（存在安全序列）才真正分配。

4. 分页地址转换（必考）
页大小 L，逻辑地址 A：页号 = ⌊A/L⌋，页内偏移 = A mod L；查页表得物理块号 B，则 物理地址 = B×L + 页内偏移。
5. 页面置换
  • OPT：淘汰未来最久不用的（理论最优，无法实现）；FIFO：先进先出，可能 Belady 异常（块增多缺页反增）；
  • LRU：淘汰最近最久未访问（基于历史）；时钟算法（最近未用，用访问位近似 LRU）。
6. 磁盘调度

SSTF 选距离当前磁头最近的请求；SCAN 电梯沿一个方向走到头再折返；CSCAN 单方向走到底后直接回起点再同向。磁头移动总道数 = 各段 |道号差| 之和。

B. 4

数据库系统

5–6 题约 7%

体系结构与数据模型

三级模式两级映像：外模式 / 概念模式 / 内模式，逻辑与物理独立性
E-R 模型：实体、属性、联系（1:1、1:N、M:N），E-R 图转关系模式
关系代数：选择 σ、投影 π、连接 ⋈（自然/外连接）、笛卡尔积、除法

SQL 语言

SELECT 单表 / 多表连接 / 嵌套 / 分组 GROUP BY·HAVING、聚集函数
DDL（CREATE/ALTER/DROP）、DML、DCL（GRANT/REVOKE）
视图（虚表）的定义与作用、索引的作用

规范化与事务

函数依赖、部分 / 传递依赖；1NF → 2NF → 3NF → BCNF 的判定
模式分解：无损连接性、保持函数依赖的判断
事务 ACID；并发控制（封锁协议、两段锁、死锁）、隔离级别
分布式数据库（两阶段提交、CAP）、数据仓库、NoSQL 基础
考点精讲：数据库的「范式判定 + 关系代数」
1. 三级模式两级映像
  • 外模式（视图级）→ 概念模式（逻辑级）→ 内模式（物理级），共三级模式。
  • 外模式/概念模式映像保证逻辑独立性；概念模式/内模式映像保证物理独立性。
2. E-R 图转关系模式（下午题核心）
  • 每个实体单独建一张表；
  • 1:1 联系可合并到任一端；1:N 联系可合并到 N 端（在 N 端加外键）；
  • M:N 联系必须单独建一张关系表，属性包含两端实体的主码（作外键）+ 联系自身的属性，其主码一般为两端主码的组合。
3. 关系代数
  • 选择 σ：按条件选行；投影 π：按列选列（去重）；连接 ⋈：按条件拼接两表；自然连接 = 同名等值连接 + 去掉重复列。
4. 范式判定（逐级）
  • 1NF：属性不可再分（原子性）；
  • 2NF：在 1NF 基础上消除非主属性对主码的部分函数依赖（针对组合主码）；
  • 3NF：在 2NF 基础上消除非主属性对主码的传递依赖；
  • BCNF：消除主属性对主码的部分/传递依赖，即每个决定因素都必须是候选码。
判定技巧：先找候选码（闭包能推出全部属性的最小集）；非主属性完全依赖于码→2NF；无非主属性传递依赖于码→3NF。
5. 事务 ACID 与并发

原子性、一致性、隔离性、持久性。两段锁协议（2PL）：加锁阶段只加锁、释放阶段只解锁，可保证可串行化但可能死锁；S 锁（共享锁/读锁）兼容、X 锁（排他锁/写锁）互斥。

传输层传输层TCP、UDP；端口

2. IP 地址分类与子网划分
  • A 类：首字节 1–126，默认掩码 /8；B 类：128–191，/16；C 类：192–223，/24；D 类组播 224–239；E 类保留。
  • 借用 n 位主机位做子网：子网数 = 2n；每子网可用主机数 = 2主机位−2（减去网络地址和广播地址）。
  • 块大小 = 256 − 掩码最后一个字节；网络地址按块大小递增，广播地址 = 下一个网络地址 −1。
路由汇聚（CIDR）：把多个连续子网取最长公共前缀，聚合为一个网络地址。
3. TCP 与 UDP、常用端口
  • TCP：面向连接、可靠、三次握手建立、四次挥手释放；UDP：无连接、不可靠、开销小、速度快。
  • 常用端口：HTTP 80、HTTPS 443、FTP 20/21、SSH 22、Telnet 23、SMTP 25、DNS 53、POP3 110、SNMP 161。
4. 常见协议作用

DNS 域名→IP（递归+迭代查询）；DHCP 自动分配 IP（发现→提供→请求→确认）；ARP 由 IP 求 MAC（局域网）；NAT 内网私有地址与公网地址转换。

1. 二叉树性质
  • 第 i 层最多 2i−1 个节点；深度为 k 的二叉树最多 2k−1 个节点。
  • 叶子数 n₀ = 度为 2 的节点数 n₂ + 1（由"边数=节点数−1"推导，几乎年年考）。
  • 完全二叉树 n 个节点的深度为 ⌊log₂n⌋+1。
2. 由遍历序列还原二叉树

前序首字符 / 后序末字符是根；用根在中序中的位置切分左右子树，递归还原。必须有中序才能唯一确定（前序+后序不行）。

3. 哈夫曼树
  • 每次取权值最小的两棵树合并，新权值为二者之和，重复到只剩一棵；无度为 1 的节点，n 个叶子共 2n−1 个节点。
  • WPL（带权路径长度）= 所有非叶子节点权值之和（比逐个叶子算路径更快捷）；哈夫曼编码是前缀码（任一编码不是另一个的前缀）。
4. 图的核心算法
  • 最小生成树：Prim 从顶点出发逐点扩展（适合稠密图），Kruskal 从边按权选（适合稀疏图），二者总权值相同。
  • 最短路径：Dijkstra 单源（不能处理负权）、Floyd 多源（任意两点，可处理部分负权）。
  • 关键路径（AOE）：关键活动 = 最早开始时间与最晚开始时间相等的活动；顶点（事件）最早 ve 取 max、最晚 vl 取 min。
5. 查找

二分查找要求顺序存储且有序，比较次数最多 ⌊log₂n⌋+1；哈希冲突处理：开放定址（线性探测、二次探测、再散列）与链地址；装填因子 α = 表中记录数/表长，越大冲突越多。

6. 排序选择
  • 要求稳定且 n 较大：归并排序；平均快、最坏 O(n²)：快排；最坏也保证 O(nlogn)：堆排、归并。
  • n 很小（如 <50）：直接插入/简单选择即可。

语言基础

编译程序原理

编译过程：词法分析 → 语法分析 → 语义分析 → 中间代码生成 → 代码优化 → 目标代码
正规式与有限自动机：NFA、DFA 及二者转换、状态数
语法分析方法：自顶向下 LL(1)、自底向上 LR（算符优先、移归约）
中间代码形式（三元式、四元式、逆波兰式后缀）、符号表

1. 编译方式 vs 解释方式

编译把整个源程序翻译成目标程序（生成可执行文件）再执行，运行快；解释方式边翻译边执行、不生成目标程序，灵活但慢。

2. 参数传递（高频）
  • 传值调用（call by value）：实参把值复制给形参，形参改变不影响实参（单向）。
  • 引用 / 传址调用（by reference）：传递地址，形参就是实参的别名，形参改变会影响实参。
3. 编译六个阶段

词法分析（识别单词 Token，输出单词符号流）→ 语法分析（按文法组词成句，构造语法树）→ 语义分析（类型检查、静态语义）→ 中间代码生成 → 代码优化 → 目标代码生成。表格管理（符号表）与出错处理贯穿全程。

4. 后缀表达式（逆波兰式）
  • 运算符紧跟在其两个操作数之后，无需括号、无优先级歧义。
  • 中缀 a+b*c → 后缀 abc*+（先乘后加）；中缀 a*(b+c) → 后缀 abc+*（括号内先算）。
5. 正规式与有限自动机

正规式 → NFA → DFA → 最小化 DFA；DFA 对每个状态和输入符号都有唯一确定的后继（无 ε 边、无多个后继），NFA 则可能有多个或空转移。两者识别能力等价。

考点精讲：加密体系、数字签名与知识产权
1. 对称加密 vs 非对称加密
类别代表算法特点
对称（私钥）DES、3DES、AES、IDEA、RC加密解密同密钥、速度快、适合大量数据，但密钥分发与管理困难
非对称（公钥）RSA、ECC、DSA公钥/私钥成对，公钥加密私钥解密，速度慢，常用于密钥交换与数字签名
摘要（散列）MD5（128 位）、SHA-1（160 位）、SHA-256不可逆、定长，用于完整性校验，不是加密
混合加密：用非对称算法安全地协商出一个对称会话密钥，再用对称算法加密大量数据（兼顾安全与速度）。
2. 数字签名与数字证书
  • 数字签名：发送方用自己的私钥对摘要加密，接收方用发送方公钥验证；可防抵赖、防篡改、验证身份，但不保证机密性。
  • 数字证书由 CA（证书权威机构）签发，用 CA 私钥绑定"公钥—身份"，PKI 是其基础设施。
3. 常见攻击与防护

  • 防火墙隔离网络、IDS 只检测告警、IPS 可阻断；HTTPS = HTTP over SSL/TLS。
4. 知识产权（高频）

考点精讲：音频/图像容量计算与压缩标准
1. 音频文件大小（字节）
容量 = 采样频率（Hz）× 量化位数（bit）× 声道数 × 时间（秒） ÷ 8。

如 44.1kHz、16 位、立体声（2 声道）：每秒 = 44100×16×2÷8 = 176400 字节 ≈ 172KB。

2. 数字图像容量
容量 = 水平像素 × 垂直像素 × 颜色深度（bit）÷ 8。
  • 颜色数与位数关系：n 位颜色深度可表示 2n 种颜色。如 256 色 = 8 位；24 位真彩色可显示 224 色。
  • 640×480 的 256 色图像：640×480×8÷8 = 307200 字节。
3. 彩色空间

4. 压缩分类与标准
  • 无损压缩：解压后数据完全一致，如霍夫曼编码、算术编码、LZW（熵编码）、PNG、FLAC。

试题一

结构化分析 · 数据流图（DFD）设计

15 分 · 必答

考查内容

  • DFD 四要素：外部实体、加工（处理）、数据存储、数据流
  • 分层结构：顶层图（上下文图）→ 0 层图 → 子图
  • 补充缺失的外部实体名（谁和系统交互）
  • 补充缺失的数据存储名（系统保存的文件/表）
  • 补充缺失的数据流（名称、起点、终点），高频问
  • 补充加工名；数据字典与加工逻辑（判定表 / 判定树 / 结构化语言）

答题技巧

  • 父图与子图平衡：父图某加工的输入/输出数据流，必须与子图一致——找遗漏数据流的第一利器
  • 数据守恒：每个加工至少一个输入、一个输出；有输入才能产生输出，不能"黑洞/奇迹/灰洞"
  • 外部实体：题干中的人物角色、外部系统（客户、管理员、银行系统）
  • 数据存储：含"XX 文件 / 表 / 库 / 清单 / 档案"字样
  • 加工名：从说明中找"动词 + 名词"结构
  • 逐句对照说明做标记，数据流名称必须能在说明中找到依据
关键：数据流的起点或终点必有一端是加工；外部实体之间、数据存储之间不能直接连数据流。答题名称尽量使用题干原文，不要自己造词。
解题五步与典型填空示范（以"图书管理系统"为例）
1圈外部实体：题干中与系统交互的人或外部系统。读者（借书/还书）、管理员（录入图书）。
2圈数据存储：含"文件/表/档案"的名词。如"图书目录文件""借书记录文件"。
3找加工：每个"动词+名词"动作，如借书登记、还书处理、图书查询。
4用父子图平衡找缺失数据流：父图中加工"借书登记"有输入"借书请求"，则 0 层图里必须有对应输入与输出。
5数据守恒校验：每个加工至少一进一出；数据流不能实体连实体、存储连存储。
典型填空：(1) 外部实体 = 读者、管理员；(2) 数据存储 = 图书目录文件、借书记录文件；(3) 缺失数据流：借书登记 → 借书记录文件（保存借书信息）；(4) 缺失数据流：读者 → 借书登记（借书请求）。
试题二

数据库分析与设计（E-R 图 + 关系模式）

15 分 · 必答

考查内容

  • 完善 E-R 图：补充实体、联系、联系类型（1:1、1:N、M:N）
  • 补充实体或联系的属性（一空可填多个）
  • E-R 图转换为关系模式，补全关系模式中的空缺
  • 判断各关系模式的主键（主码）与外键（外码）
  • 偶尔考 SQL 语句填空、关系规范化（属于第几范式）

答题技巧

  • 从题干名词找实体、动词找联系，数量描述判断 1:1 / 1:N / M:N
  • M:N 联系必须单独建一个关系：主键 = 两端实体主键组合，外键分别指向两端
  • 1:N 联系：可把"1"端主键放到"N"端关系中作外键，不必单独建表
  • 1:1 联系：外键可放在任意一端（选参与少的一端）
  • 主键能唯一标识元组；外键引用其他关系的主键
  • 属性严格从题干描述中提取，注意联系本身也可能带属性（如成绩、数量、时间）
关键：先把实体和联系全部圈出，再判断基数。多对多联系转表、主键外键是每年必考的得分点，务必练熟。
解题四步与典型填空示范（以"学生选课系统"为例）
1名词找实体：学生、课程；动词找联系：选修；由"一个学生选多门课、一门课被多个学生选"判断为 M:N。
2补属性：学生（学号、姓名、专业）、课程（课程号、课程名、学分）；联系"选修"自带属性（成绩）。
3转关系模式：两个实体各一张表，M:N 联系"选修"单独建一张表。
4标主外键：能唯一标识的作主码；联系表的两个码引用两端实体，作外码。
学生（学号，姓名，专业） 主键：学号
课程（课程号，课程名，学分） 主键：课程号
选修（学号，课程号，成绩） 主键：(学号, 课程号)；外键：学号（参照学生）、课程号（参照课程）
试题三

面向对象分析与设计（UML 建模）

15 分 · 必答

考查内容

  • 用例图：参与者、用例，include 包含、extend 扩展、用例泛化
  • 类图（最常考）：补类名、属性、方法、类间关系、多重度
  • 顺序图：对象、生命线、同步/返回消息（消息对应类的方法）
  • 状态图：状态、事件、迁移、初始态与终止态

答题技巧

  • include：基用例一定执行被包含用例（提取公共步骤）；extend：满足条件才可选扩展，箭头指向基用例
  • 类关系：题干"由…组成 / 包含 / 拥有"→聚合或组合；"是一种 / 分为"→泛化
  • 聚合（可分离）空心菱形；组合（同生共死、不可分离）实心菱形，菱形在整体端
  • 多重度对照题干数量：一个、多个（0..*）、至少一个（1..*）
  • 顺序图中的消息名通常就是接收对象所属类的方法名
  • 类名/方法名到题干和类图中找原文，注意大小写一致
关键：UML 题与试题五/六的设计模式代码题共用同一段说明和类图，理解类图结构（谁继承谁、谁持有谁）能同时帮助两题得分。
解题四步与典型填空示范（以"网上订单系统"为例）
1先判图类型：问"订单在待付款、待发货、已完成之间如何迁移"→状态图；问"下单过程中对象如何按时间传消息"→顺序图；问"系统有哪些参与者和功能"→用例图。
2判类间关系：订单与订单明细同生共死（明细脱离订单无意义）→组合（实心菱形）；订单与客户是 N:1 引用→关联。
3标多重度：一个客户可以有 0..* 张订单；一张订单必须属于 1 个客户；一张订单包含 1..* 个订单明细。
4补方法/属性：抽象类名与抽象方法在 UML 中用斜体表示；接口方法由实现类实现；可见性 + 公有、− 私有、# 保护。
典型填空：(1) 图类型 = 状态图；(2) 订单—订单明细关系 = 组合（实心菱形）；(3) 订单端到明细的多重度 = 1..*；(4) 定义公共接口的抽象方法 calc() 用斜体，由各子类实现。
试题四

算法设计与分析（代码 / 流程图填空）

15 分 · 必答 · 难度最高

考查内容

  • 给出问题描述与算法代码（C 风格）或流程图，填 3–5 个空
  • 问算法采用的设计策略、基本思想
  • 问时间复杂度（有时含空间复杂度）、结果或正确性
  • 动态规划：0-1/完全背包、最长公共子序列 LCS、最长递增子序列、编辑距离、矩阵连乘、最大子段和
  • 贪心：活动安排、找零钱、哈夫曼、最小生成树、单源最短路径
  • 分治：归并/快速排序、二分查找、汉诺塔；回溯：n 皇后、子集/排列、迷宫、旅行商

答题技巧

  • 先判策略：有重叠子问题 + 状态转移表→动态规划；每步取当前最优不回头→贪心；分解—递归—合并→分治；深度搜索+不满足回退→回溯
  • 动态规划四步：明确 dp 状态含义 → 状态转移方程 → 初始化/边界 → 遍历顺序与最终答案
  • 填空结合上下文：变量名、数组下标、循环边界、max/min 更新、递推式
  • 注意循环起止范围、临界下标、与题干示例数据对照验证
  • 即使写不全代码，也要写出策略名称、算法思想和复杂度，可拿步骤分
策略：本题是下午难点，不必死磕。背熟动态规划、贪心、回溯的经典框架与状态转移方程，先把能确定的空和"策略+复杂度"的问拿下，通常能得 8–11 分。
解题四步与典型填空示范（0-1 背包 · 动态规划）
1明确输入输出：n 件物品（重量 w[i]、价值 v[i]）、背包容量 W，求能装入的最大价值（每件至多一件）。
2定策略：每种物品"选或不选"、有重叠子问题与最优子结构 → 动态规划。
3定义状态：dp[i][j] 表示前 i 件物品在容量 j 下的最大价值。
4写状态转移与复杂度：按能否放下第 i 件分类讨论。
for i = 1..n: for j = 0..W: if (j < w[i]) dp[i][j] = dp[i-1][j]; // 放不下 else dp[i][j] = max( dp[i-1][j], // 不选 dp[i-1][j-w[i]] + v[i] ); // 选 // 答案：dp[n][W]；时间复杂度 O(nW)，空间复杂度 O(nW)
典型填空：(1) 算法策略 = 动态规划；(2) 放不下时填 dp[i-1][j]；(3) 能放下时取 max(dp[i-1][j], dp[i-1][j-w[i]]+v[i])；(4) 时间复杂度 = O(nW)。

解题四步与典型填空示范（策略模式 · Java）
1据类图判模式：一组可互换算法类实现同一接口、由上下文持有 → 策略模式。
2认角色：Strategy 抽象策略（接口）、AddStrategy 具体策略、Context 上下文。
3填继承/实现：具体类用 implements 实现接口；接口方法必须全部实现。

interface Strategy { int calc(int a, int b); } class AddStrategy implements Strategy { // 填空(1) public int calc(int a, int b) { // 填空(2) return a + b; } } class Context { private Strategy strategy; public void setStrategy(Strategy s) { this.strategy = s; } // 填空(3) public int calc(int a, int b) { return strategy.calc(a, b); // 填空(4) 多态 } }
填空要点：(1) implements Strategy；(2) public int calc；(3) 形参类型 Strategy s；(4) 调用 strategy.calc(a,b)。

面向对象程序设计 · C++（设计模式代码填空）

15 分 · 与试题五二选一

  • 填空常考：virtual、"=0"、public 继承、new 子类名、类名与方法名

1据类图判模式：与 Java 题同构，先判出策略模式。

3填虚函数：抽象基类用纯虚函数 virtual … = 0；具体类用 : public 继承并重写。

填空要点：(1) virtual int calc(int a,int b) = 0；(2) : public Strategy；(3) 形参 Strategy* s；(4) 指针调用 strategy->calc(a,b)。

备考策略与复习规划

软件设计师整体难度中等、知识面广但深度有限，科班或有编程基础者一般 1–2 个月可通关。核心是"二八法则"抓大放小、以真题驱动复习。

PHASE 01

基础学习（4–6 周）

  • 用视频 + 教程快速过一遍，建立知识框架，不纠结冷门细节
  • 优先理解：组成原理、操作系统、数据结构、数据库、网络
  • 每章配合少量练习题巩固，随手记笔记
  • 有基础者可加速，重点补自己薄弱的模块
PHASE 02

真题强化（3–4 周）

  • 上午按模块刷历年真题，整理错题与高频考点
  • 下午按题型专项突破：DFD、E-R、UML、算法、设计模式，总结答题模板
  • 背熟 23 种设计模式的意图、分类与典型场景
  • 算法题掌握动态规划、贪心、回溯经典框架
PHASE 03

冲刺模拟（1–2 周）

  • 整套限时模拟，提前熟悉机考答题与画图操作
  • 集中背记：公式、复杂度表、设计模式、易混淆概念
  • 回顾错题本，查漏补缺，不碰偏题怪题
  • 调整作息，保证考试时段状态

考场时间分配：上午 75 题 / 150 分钟，约 2 分钟一题，计算量大或没把握的先标记跳过，最后回头；专业英语可快速作答。下午 5 题 / 150 分钟，每题约 30 分钟，建议先做最有把握的数据库、UML、设计模式选答题，DFD 约 25–30 分钟，把算法难题放最后、先拿"策略 + 复杂度"的步骤分，留约 10 分钟检查名称与漏题。
